# Uptrend 切替後の比較運用

[切替台帳](uptrend-cutover-20261118.md)の残件を処理する手順。
定義差の比較規則をここで定める。本番の表示・取引判定コードへの適用は本書だけでは完了しない。

## 比較時の規則

| 比較条件 | 判定・扱い |
|---|---|
| 同じ定義・同じ市場日・同じ観測窓 | Count/Totalだけでなく、分子・母数の銘柄集合を比較する |
| 同じ定義・同じ市場日だが観測窓が違う | 時刻差あり。数値差だけで障害・連続性を判定しない |
| 混合集計と株式限定 | 定義差あり。増減を市場の改善・悪化として集計しない |
| 実行版・定義・観測時刻が不明 | 比較未確認。日付や近い母数から定義を推定して確定しない |
| 取得失敗、欠損、無効な母数 | 未取得。ゼロに置き換えない |

比較表・引き継ぎ資料では、値に「混合集計」「株式限定」「定義未確認」のいずれかを併記し、
市場日、観測開始/終了UTC、実行コミット、資料への参照を残す。
Dashboardの全市場・Financialは従来対象を維持する混合集計。
上流の実行定義は本番版で確認し、マージ済みソースの定義で代用しない。

79銘柄や特定標本の比率差を固定補正として過去へ適用しない。
株式限定のMA・閾値・統計と旧定義の履歴は、同じ系列として成績比較しない。
切替後1〜9観測の10MAは「定義混在」、10観測目は「新定義のみ」。
MAの差分による傾きは11観測目から両辺が新定義のMAになる。
各worksheetの有効観測数で数える。これは全期間の互換性や閾値の再検証を保証しない。
本書は比較・報告の規則であり、既存の取引シグナルを自動変更するものではない。

## 最初の株式限定保存日の確定

上流Issue [#2](https://github.com/tradermonty/stock-trading-system/issues/2)を
本番保存の受入先として継続使用する。運用ホストが判明したら次を読み取りで収集する。

1. 定期実行の定義から、実行ホスト・時刻/タイムゾーン・作業ディレクトリ・起動ファイルを特定する。
2. 実際の配置コミットを確認する。`git rev-parse HEAD`だけでは不足する場合、dirty差分やコンテナ/配布版も確認する。APIキーなどの値は記録しない。
3. 最初の成功実行のログから、観測時刻、集計定義、分子/母数、書き込み市場日、対象worksheetを確認する。ログを得るために取引・Sheets更新スクリプトを実行しない。
4. 対象Sheetsの該当行を読み取り、ログとCount/Totalを突合する。行があるだけでは、その定義で書かれた証拠にはしない。
5. 最終混合集計日から境界を追い、失敗・再実行・既存行上書きも確認する。分母が減った日だけから切替日を決めない。
6. worksheetごとに境界が異なる場合は個別に記録する。未確認のセクターに全市場の境界を流用しない。

保存記録の必須項目：

| 項目 | 未確認時の値 |
|---|---|
| worksheet、保存先の行/範囲、証拠への参照 | 未確認 |
| 最終混合集計日 / 最初の株式限定保存市場日 | 未確認 |
| 実行コミット/配布版、dirty差分の有無 | 未確認 |
| 観測開始/終了UTC、書き込み成功時刻UTC | 未確認 |
| 分子/母数、シート読戻し値、再実行/上書きの有無 | 未確認 |

Sheetsは日付行に現在の値を持つため、過去に上書きされた事実を現在値だけから復元できない。
ログや版の証拠が得られなければ、切替台帳は未確認を維持する。
アクセス制限のあるシートのID・生データ・ホスト情報は、公開リポジトリに転記せず非公開の監査資料で保持する。

## 2026年12月7日前後の再検証

可能であれば最後の切替前営業日（12月4日）の引け後と、12月7日の引け後に実施する。
予定日から実際の提供開始時刻を推定せず、取得したUTC時刻と取引カレンダーの文脈を記録する。
これは実施手順であり、自動実行は設定していない。

Dashboardの確認済みコード・依存環境で、毎回新しい出力名を指定する：

```sh
python compare_finviz_exports.py --output /tmp/uptrend-finviz-20261204-pre.json
python compare_finviz_exports.py --output /tmp/uptrend-finviz-20261207-post.json
```

上の2コマンドはそれぞれ指定日の確認時に実行する。今日実行してその日の観測として扱わない。
認証は既存の`FINVIZ_API_KEY`設定を用い、コマンド引数・ログ・レポートにキーを転記しない。
全7必須worksheet（全市場、金融、半導体、ETF、3ファンド業種）の分子/母数を対象とする。
部分サンプルでは移行全体を受け入れない。

- 終了0：その観測窓で必須の旧新集合が一致。将来の一致保証ではない。
- 終了2：差分、取得不能または不完全。ゼロ件・比較成功として扱わない。
- 終了1：設定/出力の失敗。観測証拠として扱わない。

上流側も固定版の[比較手順](https://github.com/tradermonty/stock-trading-system/blob/364ee4a89c243f79db47d6f0e803d48adb2e2ad6/docs/validation/finviz-cutover-20261118.md)で、
株式限定による除外を含めて説明する。上流ツールの終了1は意図した定義差でも起こるため、Dashboardツールの終了コードと混同しない。
旧エンドポイント廃止で比較不能になった場合は、HTTP成功した新エンドポイントだけで旧系列との連続性を認定しない。
最後の確認済みの銘柄集合・フィルター・経路と照合し、影響系列の公開可否をレビューする。
本番の停止・デプロイ・過去履歴の書き換えを、この手順から自動実行しない。
